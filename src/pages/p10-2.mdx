# 10-2 API 규격 요점: 보호·해석·시험의 질문을 나눕니다

시험 성적서에는 API 617, 보호 시스템 도면에는 API 670, 로터 해석 보고서에는 API 684 계열이 적혀 있습니다. 진동 수치 하나를 확인하려는데 문서가 왜 이렇게 많을까요?

이 페이지는 문서 번호를 외우는 대신 **지금 확인하려는 질문에 맞는 문서와 증거**를 찾습니다. 수치 허용값과 조항은 적용 판본·계약·보유 원문에서 대조합니다.

<Callout type="idea" title="이 페이지를 다 읽으면">

1. API 670, 684 계열, 612/616/617의 역할을 구별할 수 있다.
2. 보호 시스템을 센서부터 출력까지 연결해서 확인할 수 있다.
3. AF·분리여유·안정성 해석에서 필요한 가정과 한계를 설명할 수 있다.
4. 공장·현장 시험의 조건과 평가량을 맞춰 읽을 수 있다.
5. 적용 요구·증거·결론이 이어지는 검토 기록을 남길 수 있다.

</Callout>

## 1. 문서 번호를 고르기 전에: 무엇을 확인하나요

API는 석유·화학·가스 산업 장비와 시스템에 관한 문서를 발행합니다. 회전기계 관련 문서도 장비 설계·시험, 보호 시스템, 해석 방법의 설명처럼 목적이 나뉩니다.

<Figure {...F.purposes} />

그림 1의 **API 670**은 기계 보호 시스템, **API 684 계열**은 로터 동역학과 밸런스 해석을 읽는 튜토리얼, **API 612·616·617**은 각각 특수 목적 ST, GT, 축류·원심 압축기 및 익스팬더 압축기 관련 장비 문서입니다. 이 역할 구분은 API의 공식 카탈로그에서 확인할 수 있습니다. <Cite ids={['R-79']} />

<Callout type="term" title="규격·권고 실무·기술 보고서">

API 문서는 Standard, Recommended Practice(RP), Technical Report(TR)처럼 종류가 다릅니다. 이름에 붙은 종류·판본과 계약에서 어떤 문서를 채택했는지까지 확인합니다. 튜토리얼의 설명을 장비 규격의 인수 조항과 같은 것으로 취급하지 않습니다.

</Callout>

| 지금의 질문 | 먼저 찾을 문서·자료 |
|---|---|
| 채널·센서·알람·보호 출력이 어떻게 구성되나 | API 670·제조사 문서·설비 보호 설계 |
| 임계속도·불평형 응답·안정성을 어떻게 해석하나 | API 684 계열·적용 장비 규격·해석 보고서 |
| ST·GT·압축기의 시험과 인수 요구는 무엇인가 | API 612·616·617의 적용 문서·계약 |
| 실제 설치 설비의 진동을 어떻게 평가하나 | P10-1의 ISO 적용 범위·제조사·운전 조건 |

API 684는 기존 RP 684, TR 684-1 등의 자료로도 만나게 됩니다. 공식 카탈로그의 문서 종류·제목·판본과 손에 든 자료를 맞춰 보세요. 이 페이지는 계열의 해석 주제를 안내하며 특정 판본의 요구 조항을 재현하지 않습니다. <Cite ids={['R-07', 'R-79']} />

<Callout type="warn" title="'API를 따랐다'라는 한 줄만으로는 부족합니다">

기계 종류, 적용 문서의 판본, 채택한 계약 조건과 예외를 밝혀야 합니다. 최신 카탈로그의 문서와 해당 설비 계약의 판본이 다르면 차이와 적용 근거를 남깁니다. 공식 문서 목록은 2026-10-12에 확인했습니다.

</Callout>

## 2. API 670: 센서부터 보호 출력까지 이어 봅니다

프로브가 정상이라고 보호 기능 전체가 확인된 것은 아닙니다. <a href={withBase('/p3-5/')}>P3-5</a>에서 배운 측정·보호 경로를 그림 2처럼 연결해 봅시다.

<Figure {...F.protection} />

입력에서는 센서 위치·방향·단위·범위와 신호 유효성을 확인합니다. 상대 축 진동이라면 프로브 시스템의 갭과 런아웃, 하우징 진동이라면 센서 부착과 신호 경로가 맞는지 봅니다.

판단 부분에서는 채널별 설정, 알람과 트립의 역할, 논리가 어떤 상태에서 작동하는지 확인합니다. **투표 논리(voting)**는 여러 채널의 상태를 조합해 동작을 정하는 방식입니다. **바이패스(bypass)**는 지정 기능을 일시적으로 제외하는 상태이며, 누가 언제 적용했고 언제 복구했는지가 기록돼야 합니다.

출력에서는 논리 결과가 실제 지정 동작으로 이어지는지 승인된 기능 시험으로 확인합니다. 이 세 단계는 보호 설계를 검토하기 위한 학습 묶음이며, API 670의 조항 순서나 모든 요구사항을 대신하는 목록은 아닙니다. 보호 문서의 적용 범위는 공식 자료에서 찾고, 상세 조건은 원문과 시스템 설계에서 대조합니다. <Cite ids={['R-53', 'R-79']} />

<Callout type="field" title="설정표에 붙일 근거">

채널·단위·평가량·운전 상태·경보 논리·시간 조건과 설정 이유, 적용 문서, 변경 승인을 함께 남깁니다. 입력 유효성과 보호 기능 시험 결과도 같은 채널 번호로 연결합니다.

</Callout>

<Callout type="warn" title="'C/D 경계가 곧 트립 설정이다'">

P10-1의 크기 구간과 보호 출력은 목적이 다릅니다. 크기 경계만 복사하거나, 진단을 위해 보호 기능을 임의로 바꾸지 않습니다. 시험에 필요한 상태 변경은 승인된 설비 절차에 따라 수행합니다.

</Callout>

## 3. AF와 분리여유: 계산값과 요구값을 구별합니다

해석 보고서에 AF와 SM이 적혀 있으면 숫자가 작거나 크다는 것만으로 합격을 말할 수 있을까요? 먼저 그 숫자가 어느 응답과 어느 운전 범위에서 나온 것인지 확인합니다.

<Figure {...F.peak} />

그림 3은 폭 읽기를 위한 가상 정규화 봉우리입니다. 피크는 3000 rpm, 피크 진폭의 $1/\sqrt2$ 지점은 2820·3180 rpm입니다. <a href={withBase('/p4-1/')}>P4-1의 Half-power AF</a>를 되짚으면 다음과 같습니다.

$$
AF=\frac{N_c}{N_2-N_1}
=\frac{3000}{3180-2820}\approx8.33
$$

$N_c$는 피크 회전수, $N_1$·$N_2$는 피크 양쪽의 0.707배 지점입니다. 이 가상 봉우리는 폭의 계산만 보여 주며 실제 로터의 운동방정식 결과나 API 허용 경계가 아닙니다.

<Callout type="example" title="같은 임계속도라도 운전 범위와의 위치가 필요합니다">

피크 3000 rpm과 표시 운전점 3600 rpm의 차이는 600 rpm입니다. P4-1의 개념식 $100\lvert N_{op}-N_c\rvert/N_{op}$로 나타내면 16.7%입니다. 이것은 운전점을 분모로 정한 학습 계산입니다. 실제 분리여유 요구는 적용 문서의 상·하한, 기준 회전수와 정의를 대조합니다.

</Callout>

보고서에서는 어느 모드·센서·가진·온도·지지 조건으로 계산했는지, 분리여유가 어느 운전 범위의 어느 쪽인지 확인합니다. AF에 따라 요구되는 분리여유를 검토하는 설명은 API 684 계열에서 찾고, 실제 요구는 적용 장비 문서와 판본에서 대조합니다. <Cite ids={['R-07']} />

<Callout type="warn" title="'8.33 또는 16.7%면 합격이다'">

둘 다 이 페이지의 가상 계산값입니다. 요구값이 아닙니다. 가까운 모드, 모드 간 상쇄, 작은 측정 참여와 넓은 피크에서는 단순 Half-power 해석의 의미가 달라질 수 있습니다. <a href={withBase('/p8-1/')}>P8-1의 여러 모드 응답</a>과 함께 읽습니다.

</Callout>

## 4. 안정성 보고서: 가정과 민감도를 함께 봅니다

임계속도가 운전점과 떨어져 있어도 서브싱크로너스 성분이 자랄 수 있었습니다. <a href={withBase('/p4-4/')}>P4-4</a>의 감쇠·교차연성·로그 감쇠를 다시 떠올려 보세요.

<Figure {...F.model} />

그림 4의 입력에는 축·질량·베어링·씰뿐 아니라 운전 온도, 하중, 윤활 조건과 동계수가 들어갑니다. 같은 축 모델이라도 이 조건이 바뀌면 모드 감쇠와 응답이 달라집니다. 계산 가정을 실제 운전 조건과 비교해야 합니다.

**Level I·Level II** 같은 안정성 해석 단계는 그 목적과 적용 판본을 함께 읽습니다. API 617의 8판을 다룬 공개 연구에서는 이 해석을 설계 단계의 교차연성 영향·운전 범위 내 모드 감쇠 검토로 설명합니다. 현행 장비 문서가 요구하는 단계와 수행 조건은 적용 판본·계약에서 대조하고, 입력 계수와 모드 결과로 판단의 근거를 남깁니다. <Cite ids={['R-85']} />

<Callout type="term" title="민감도 검토 (Sensitivity study)">

입력 가정을 바꿨을 때 결론이 얼마나 달라지는지 보는 검토입니다. 베어링 하중·씰 교차연성·지지 강성의 가능한 범위를 바꿔 모드 감쇠·피크·간극 응답의 변화를 확인합니다.

</Callout>

| 보고서 항목 | 읽을 질문 |
|---|---|
| 모델 | 어떤 축·지지·씰·결합 장비를 포함했나 |
| 운전점 | 속도·부하·온도·하중 조건이 무엇인가 |
| 응답 | 가진 위치·크기, 센서 위치와 간극 기준은 무엇인가 |
| 안정성 | 모드별 감쇠·성장, 입력 계수의 출처는 무엇인가 |
| 검증 | 민감도와 시험 비교에서 남은 차이는 무엇인가 |

<Callout type="field" title="예측과 시험의 차이도 결과입니다">

계산 피크와 기동 시험 피크가 다르면 한쪽 숫자를 지우기 전에 열 상태·지지·센서 위치·slow roll 보상·모드 중첩을 확인합니다. 어떤 입력을 바꿔 설명할 수 있고 무엇이 미확인인지 기록합니다.

</Callout>

## 5. API 612·616·617: 시험 조건과 평가량을 같이 읽습니다

공장 시험에서 확인한 값이 설치 후 자료와 다를 때 무엇을 비교해야 할까요? 같은 회전수만으로 시험이 같다고 할 수는 없습니다.

<Figure {...F.acceptance} />

그림 5에서 시험 종류, 부하·열 상태·보조 설비, 센서·평가량·대역을 함께 묶습니다. **기계적 운전 시험(mechanical running test)**은 기계의 운전 거동을 확인하는 시험이고, **성능 시험(performance test)**은 장비가 지정 성능을 내는지 확인하는 시험입니다. 적용 문서가 어떤 시험을 요구하는지, 시험 범위가 무엇인지 확인합니다.

612는 특수 목적 ST, 616은 GT, 617은 축류·원심 압축기 및 익스팬더 압축기를 다루는 장비 문서입니다. 각 기계의 설계·시험·관련 요구를 찾는 출발점이며, 아래 묶음은 이 사이트의 확인 질문입니다. 원문 요구사항의 표를 재현한 것이 아닙니다. <Cite ids={['R-79']} />

| 묶어 둘 자료 | 함께 적을 내용 |
|---|---|
| 시험 상태 | 시험 종류·속도 범위·부하·열 안정 상태 |
| 측정 경로 | 채널·센서 위치·단위·대역·교정·수집 설정 |
| 평가 근거 | 적용 문서·판본·계약·제조사 조건 |
| 결과 | 지정 항목의 시험값·원자료·해석과의 비교 |
| 예외 | 시험하지 못한 조건·차이·추가 확인·승인 |

<Callout type="warn" title="'공장 시험값을 현장 기준선으로 그대로 쓴다'">

설치 지지, 배관·기초, 결합 축계와 운전 조건이 다를 수 있습니다. 현장 기준선은 설치 후 비교 조건을 명시해 기록하고, 공장 시험과의 차이는 별도 근거로 설명합니다.

</Callout>

## 6. 적합성 결론: 요구에서 증거까지 추적합니다

검토자가 성적서를 다시 읽을 때 같은 결론에 도달할 수 있어야 합니다. 문서 번호 뒤에 어느 요구를 어떤 자료로 확인했는지 연결해 봅시다.

<Figure {...F.trace} />

그림 6은 **추적성(traceability)**, 즉 요구·자료·결론 사이의 경로가 남는 기록입니다. 'API 617 충족'이라는 넓은 문장 대신 적용 판본·해당 항목·시험 조건·자료 위치·검토 결론을 묶습니다.

조건을 확인하지 못했으면 '미확인'이라고 씁니다. 충족하지 못한 결과와 수행하지 못한 시험도 구별합니다. 예외를 승인받았다면 승인 범위와 남은 위험·후속 조치가 함께 남아야 합니다.

<Callout type="example" title="수치 없이도 검토 경로를 쓸 수 있습니다">

'계약에서 채택한 판본의 해당 시험 항목을 검토했다. 시험 조건과 채널 정보는 시험 기록에, 원자료는 지정 파일에 연결했다. 현장 열간 조건은 미확인으로 남겨 추가 확인을 권고했다.' 이렇게 범위와 증거 위치를 적으면 다음 검토자가 미확인 항목을 찾을 수 있습니다.

</Callout>

## 7. 정리

| 문서·주제 | 기억할 질문 |
|---|---|
| API 670 | 센서·신호·보호 논리·출력은 확인됐나 |
| API 684 계열 | AF·SM·안정성 해석의 가정과 의미는 무엇인가 |
| API 612·616·617 | 어느 장비의 어떤 시험·인수 조건인가 |
| AF·SM | 계산 정의와 운전 범위·요구값을 구별했나 |
| 해석 검증 | 입력 출처·민감도·시험 차이는 남겼나 |
| 적합성 결론 | 판본·요구·증거·예외를 추적할 수 있나 |

---

## 8. 확인 문제

<details>
<summary><strong>Q1. 보호 시스템, 해석 튜토리얼, GT 장비 문서는 각각 어디서 찾나요?</strong></summary>

API 670, API 684 계열, API 616입니다. 실제 적용 종류·판본·계약도 함께 확인합니다.
</details>

<details>
<summary><strong>Q2. 가상 피크 3000 rpm, 0.707배 지점 2820·3180 rpm의 AF는?</strong></summary>

$3000/(3180-2820)=8.33$입니다. 이 숫자는 폭의 산술 예이며 API 허용값이 아닙니다.
</details>

<details>
<summary><strong>Q3. 같은 피크와 운전점 3600 rpm의 P4-1 개념 SM은?</strong></summary>

$100\times600/3600=16.7\%$입니다. 실제 규격 요구에는 운전 범위와 분모 정의 등 적용 원문을 대조해야 합니다.
</details>

<details>
<summary><strong>Q4. 임계속도가 운전점에서 떨어져 있으면 안정성도 확인됐나요?</strong></summary>

아닙니다. 모드 감쇠·교차연성·운전점·계수 출처와 민감도 등 안정성 검토가 별도로 필요합니다.
</details>

<details>
<summary><strong>Q5. 시험하지 못한 열간 조건을 보고서에서 어떻게 다루나요?</strong></summary>

미확인 조건과 이유, 추가 시험 또는 검토 계획을 명시합니다. 미확인을 충족으로 바꾸지 않습니다.
</details>

<details>
<summary><strong>Q6. 공장·현장 자료가 같은 회전수면 같은 기준으로 비교할 수 있나요?</strong></summary>

부하·열 상태·지지·결합 장비·측정량·대역까지 확인해야 합니다. 같은 회전수는 비교 조건 중 하나입니다.
</details>

다음 페이지(P10-3)에서는 유효한 자료에서 가설을 좁히고, 확인 시험과 권고를 보고서로 연결합니다.
