# 10-2 API 규격 요점: 기계의 일생에서 문서를 찾습니다

시험 성적서에는 API 617, 보호 시스템 도면에는 API 670, 로터 해석 보고서에는 API 684가 적혀 있습니다. 진동 하나를 보는데 문서가 왜 이렇게 많을까요? 각 문서는 기계의 일생에서 **다른 때, 다른 질문**에 답합니다.

이 페이지는 문서 번호를 외우는 대신 그 질문과 생각을 따라갑니다. 규격의 허용값·경계값은 옮기지 않으므로, 계산 예는 P4-1·P4-4의 학습 모델로 합니다.

<Callout type="idea" title="이 페이지를 다 읽으면">

1. API 장비 규격(617·612·616)·684·670이 기계의 일생 중 언제 쓰이는지 말할 수 있다.
2. 보호 시스템 사양서를 센서에서 트립 출력까지 따라가며 확인할 것을 고를 수 있다.
3. AF가 클수록 더 큰 분리여유를 두는 이유를 임계속도 예측 오차로 설명할 수 있다.
4. Level I·II 안정성 해석의 생각(교차연성과 로그 감쇠, 여유)을 설명할 수 있다.
5. 기계적 운전 시험의 흐름을 알고, 요구 → 증거 → 결론으로 적합성 기록을 남길 수 있다.

</Callout>

## 1. 문서는 언제 쓰이나요

API는 석유·화학·가스 산업 장비의 문서를 냅니다. 회전기계의 진동과 관련된 것은 크게 셋입니다. 장비 규격, 해석 튜토리얼, 보호 시스템 규격입니다. <Cite ids={['R-79']} />

<Figure {...F.purposes} />

그림 1에서 읽을 수 있는 것:

- **장비 규격** — API 617(축류·원심 압축기·익스팬더 압축기), 612(특수 목적 ST), 616(GT)이 설계 단계의 해석 요구(임계속도·불평형 응답·안정성)와 공장 시험의 요구를 담습니다. 분리여유나 안정성 기준이 실제로 "요구"되는 곳은 여기입니다.
- **API 684**는 그 해석을 어떻게 하고 어떻게 읽는지 설명하는 튜토리얼입니다(RP 684, 2019년부터 TR 684-1). 요구 조항 자체가 아닙니다.
- **API 670**은 설치 뒤 기계 보호 시스템 — 센서·모니터·트립 — 의 규격입니다. 운전 중 크기·변화 평가는 P10-1의 ISO 20816이 맡습니다.

<Callout type="term" title="규격·권고 실무·기술 보고서">

API 문서는 Standard, Recommended Practice(RP), Technical Report(TR)로 종류가 다릅니다. 튜토리얼(684)의 설명을 장비 규격의 인수 조항과 같은 무게로 읽지 않습니다. 2026-10-12에 확인한 현행 판은 API 670 6판(2025), 617 9판(2022), 612 8판(2020), 616 6판(2022)입니다.

</Callout>

<Callout type="warn" title="'API를 따랐다' 한 줄">

어느 문서의 몇 판인지, 계약이 그중 무엇을 채택하고 무엇을 예외로 했는지가 없으면 검토할 수 없습니다. 설비가 만들어질 때의 판과 지금의 판이 다르면 둘 다 적습니다.

</Callout>

## 2. API 670: 센서에서 트립 출력까지 따라갑니다

<a href={withBase('/p3-5/')}>P3-5</a>에서 Alert·Danger, 시간 지연, 보팅, 기동 중 트립 배율, Not OK를 직접 조작해 봤습니다. 여기서는 그 기능들이 사양서의 어디에 있는지 한 줄로 이어 봅니다.

<Figure {...F.protection} />

그림 2에서 읽을 수 있는 것:

- 신호는 센서 → 드라이버(프록시미터) → 모니터 채널 → 릴레이 출력 → 기계 정지로 갑니다. 각 칸 아래쪽의 "확인"이 그 칸에서 볼 것입니다.
- 모니터의 **버퍼 출력**은 상태감시·진단 장비로 갈라져 나갑니다. 진단 장비를 연결하거나 떼는 일이 보호 기능에 끼어들지 않게 하는 구조입니다.
- 마지막 칸의 **기능 시험**과 **바이패스(Bypass) 기록**이 빠지면, 센서가 정상이어도 보호가 실제로 동작하는지 알 수 없습니다.

<Callout type="field" title="설정표에 붙일 근거">

채널마다 단위·방향·평가량, Alert·Danger 값과 그 근거(P10-1 §5의 기준선·여유), 지연·보팅·기동 처리, 적용 판본, 변경 승인을 같은 채널 번호로 묶습니다. 기능 시험 결과도 그 번호에 붙입니다.

</Callout>

## 3. AF와 분리여유를 읽습니다

해석 보고서에 "AF 9.84, SM 16.7 %"가 적혀 있다면 무엇을 읽어야 할까요? <a href={withBase('/p4-1/')}>P4-1</a>의 예시 로터로 두 숫자를 다시 봅시다.

<Figure {...F.peak} />

그림 3의 피크는 3000 rpm, 0.707배 지점은 2866.5·3171.5 rpm입니다.

$$
AF=\frac{N_c}{N_2-N_1}=\frac{3000}{3171.5-2866.5}\approx9.84,\qquad
SM=100\,\frac{\lvert N_{op}-N_c\rvert}{N_{op}}=100\times\frac{600}{3600}\approx16.7\ \%
$$

$N_c$는 피크 회전수, $N_1$·$N_2$는 피크 양쪽의 0.707배 지점, $N_{op}$는 운전 회전수입니다. 실제 보고서에서는 이 숫자가 **어느 모드, 어느 센서, 어떤 가진·온도·지지 조건**에서 나왔는지, 분리여유가 운전 범위의 위쪽 끝과 아래쪽 끝 중 어디에서 잰 것인지를 함께 봅니다. 장비 규격은 분리여유를 운전 범위의 끝에서 정의합니다. <Cite ids={['R-07']} />

<Callout type="warn" title="'봉우리가 하나니 Half-power면 충분하다'">

가까운 두 모드가 겹치거나 센서가 모드의 마디 근처에 있으면 봉우리 폭이 실제 감쇠를 말하지 않습니다. <a href={withBase('/p8-1/')}>P8-1의 여러 모드 응답</a>처럼 위상과 여러 센서를 함께 봅니다.

</Callout>

## 4. AF가 크면 왜 분리여유를 더 두나요

장비 규격은 AF에 따라 요구하는 분리여유를 달리 둡니다. AF가 충분히 작은(감쇠가 큰) 모드에는 분리여유를 요구하지 않고, AF가 클수록 더 넓은 여유를 요구합니다. 왜 그럴까요? 해석이 예측한 임계속도가 **틀릴 수 있기 때문**입니다. <Cite ids={['R-07', 'R-85']} />

<Figure {...F.uncertainty} />

그림 4는 같은 배치(예측 임계속도 3000 rpm, 운전 3600 rpm)에서 실제 임계속도가 10 % 높은 3300 rpm이었다고 놓고 운전점 응답을 비교합니다.

- 뾰족한 AF 10에서는 운전점 응답이 편심의 3.16배 → 5.43배, **1.72배**가 됩니다.
- 펑퍼짐한 AF 2.5에서는 2.21배 → 2.50배, **1.13배**입니다.

같은 예측 오차가 뾰족한 봉우리에서 훨씬 크게 번집니다. 그래서 AF가 클수록, 오차가 있어도 봉우리 기슭에 머물 만큼 운전점을 멀리 둡니다.

<Callout type="try">

1. 기본값(AF 10, SM 16.7 %, 오차 +10 %)에서 운전점 응답이 예측의 몇 배인지 읽습니다.
2. AF만 2.5로 바꿉니다. 같은 오차의 영향은?
3. AF를 10으로 되돌리고, 1.13배로 묶이려면 SM을 얼마까지 늘려야 하는지 찾아봅니다.
4. 오차를 +20 %로 올립니다. 실제 임계속도는 어디에 있나요?

</Callout>

<SeparationMarginLab client:visible />

1번은 1.72배, 2번은 1.13배입니다. 3번에서 AF 10은 SM을 40 %까지 늘려야 1.13배가 됩니다(30 %에서도 1.24배). AF 2.5가 16.7 %로 얻는 안심을 AF 10은 그 두 배가 넘는 여유로 얻는 셈입니다. 4번에서는 실제 임계속도가 운전점 3600 rpm에 올라타 응답이 봉우리 높이(≈ AF = 10)가 됩니다. 실제 요구 분리여유의 식과 AF 구분은 적용 장비 규격에서 확인합니다.

## 5. 안정성 해석: Level I과 Level II

임계속도에서 멀리 떨어져 있어도 서브싱크로너스 진동이 자랄 수 있었습니다. <a href={withBase('/p4-4/')}>P4-4</a>에서 교차연성 $q$가 커지면 전진 모드의 감쇠가 줄고, 로그 감쇠 $\delta$가 0이 되는 곳이 안정 한계라는 것을 봤습니다.

<Figure {...F.stability} />

그림 5는 P4-4의 학습 모델에서 $q$를 키울 때의 $\delta$입니다. $q=0$에서 $\delta=0.315$, $q$가 강성 $k$의 10 %($q_0$)에 닿으면 $\delta=0$입니다.

API 617은 7판(2002)부터 이 생각을 두 단계로 씁니다. <strong>Level I</strong>은 임펠러·블레이드가 만드는 공력 교차연성을 추정식으로 넣은 간이 해석입니다. 첫 전진 모드의 로그 감쇠와, $\delta=0$이 되는 교차연성 $q_0$가 예상값 $q_a$보다 얼마나 큰지를 봅니다. 그림 5의 가상 $q_a$(k의 4 %)라면 $\delta=0.189$, 여유 $q_0/q_a=2.5$입니다. 이 간이 검토를 넘지 못하거나 해당하는 기계는 <strong>Level II</strong>로 갑니다 — 씰·밸런스 피스톤처럼 교차연성과 감쇠를 바꾸는 요소를 모두 넣은 상세 해석입니다. 판정 기준값은 적용 판본에서 확인합니다. <Cite ids={['R-90', 'R-85']} />

<Callout type="term" title="민감도 검토 (Sensitivity study)">

입력 가정을 바꿨을 때 결론이 얼마나 달라지는지 보는 검토입니다. 베어링 하중·씰 계수·지지 강성의 가능한 범위를 바꿔 로그 감쇠와 응답이 어떻게 움직이는지 봅니다. 그림 5의 곡선이 왼쪽으로 조금만 밀려도 여유가 줄어드는 기계라면, 결론보다 이 민감도가 더 중요한 정보입니다.

</Callout>

| 보고서 항목 | 읽을 질문 |
|---|---|
| 모델 | 축·베어링·씰·결합 장비 중 무엇을 넣었나 |
| 운전점 | 속도·부하·온도·베어링 하중 조건은 |
| 응답 | 가진 위치·크기, 센서 위치와 간극 기준은 |
| 안정성 | Level I·II 중 어디까지, 모드별 로그 감쇠, 입력 계수의 출처는 |
| 검증 | 민감도, 시험과의 차이와 그 설명은 |

## 6. 공장 시험: 기계적 운전 시험의 흐름

해석은 예측이고, 공장 시험은 그 예측을 처음 확인하는 자리입니다. 시험값을 읽으려면 어떤 상태에서 잰 값인지부터 알아야 합니다.

<Figure {...F.acceptance} />

그림 6에서 읽을 수 있는 것:

- <strong>기계적 운전 시험(Mechanical running test)</strong>은 최대 연속 회전수(MCS)까지 올려 베어링 온도가 안정되기를 기다리고, 트립 회전수를 잠깐 확인한 뒤, MCS에서 정해진 시간 동안 연속 운전하며 진동·온도를 평가하는 시험입니다.
- 감속하며 기록한 Bode로 임계속도와 AF를 재서 §3·§4의 해석과 견줍니다. 차이가 크면 모델의 지지·베어링 가정을 다시 봅니다.
- <strong>성능 시험(Performance test)</strong>은 별도로, 장비가 지정 성능을 내는지 확인합니다. 구간 길이·판정 항목은 장비 규격과 계약에서 확인합니다. <Cite ids={['R-79']} />

<Callout type="warn" title="'공장 시험값을 현장 기준선으로 그대로 쓴다'">

공장의 시험대와 현장의 기초·배관·결합 축계는 다릅니다. 현장 기준선은 설치 뒤 같은 운전 조건에서 새로 잡고, 공장 시험과의 차이는 따로 설명합니다.

</Callout>

## 7. 적합성 결론: 요구에서 증거까지

검토자가 성적서를 다시 읽어도 같은 결론에 도달해야 합니다. 문서 번호 뒤에 어느 요구를 어떤 자료로 확인했는지 이어 봅시다.

<Figure {...F.trace} />

그림 7은 <strong>추적성(Traceability)</strong>, 곧 요구·증거·결론 사이의 길이 남는 기록입니다. 결론은 충족·미충족·미확인 중 하나입니다. 확인하지 못한 조건은 "미확인"으로 두고 이유와 다음 시험 계획을 붙입니다. 미확인을 충족으로 바꾸지 않습니다.

<Callout type="example" title="숫자 없이 쓰는 검토 문장">

"계약이 채택한 617 판의 기계적 운전 시험 항목을 검토했다. 시험 조건·채널표는 시험 기록 3장, 원자료는 지정 폴더에 있다. 감속 Bode의 1차 임계속도는 해석보다 4 % 낮았고 그 차이를 지지 강성 가정으로 설명했다. 현장 열간 조건은 미확인으로 남기고 시운전 때 확인을 권고한다."

</Callout>

## 9. 확인 문제

<details>
<summary><strong>Q1. 압축기의 분리여유 "요구"는 API 684와 617 중 어디에 있나요?</strong></summary>

장비 규격인 617에 있습니다. 684는 그 해석을 설명하는 튜토리얼입니다.
</details>

<details>
<summary><strong>Q2. 피크 3000 rpm, 0.707배 지점 2866.5·3171.5 rpm, 운전 3600 rpm의 AF와 SM은?</strong></summary>

$AF=3000/305.0\approx9.84$, $SM=100\times600/3600\approx16.7\ \%$입니다. 허용값이 아니라 읽은 값입니다.
</details>

<details>
<summary><strong>Q3. 같은 SM에서 임계속도 예측이 10 % 틀렸을 때, AF 10과 AF 2.5 중 어느 쪽이 더 위험한가요?</strong></summary>

AF 10입니다. 운전점 응답이 1.72배(AF 2.5는 1.13배)로 뜁니다. 그래서 AF가 클수록 더 큰 분리여유를 둡니다.
</details>

<details>
<summary><strong>Q4. 그림 5에서 예상 교차연성이 k의 4 %라면 Level I의 여유 $q_0/q_a$는?</strong></summary>

$q_0$가 k의 10 %이므로 $10/4=2.5$입니다. 그때의 로그 감쇠는 0.189입니다. 기준값과의 비교는 적용 판본에서 합니다.
</details>

<details>
<summary><strong>Q5. 진단 장비를 모니터의 버퍼 출력에 연결하는 이유는?</strong></summary>

진단 장비를 연결·분리해도 보호 경로(모니터 → 릴레이 → 트립)에 끼어들지 않게 하기 위해서입니다.
</details>

<details>
<summary><strong>Q6. 시험하지 못한 열간 조건을 보고서에서 어떻게 다루나요?</strong></summary>

"미확인"으로 두고 이유와 다음 확인 계획을 적습니다. 충족으로 바꾸지 않습니다.
</details>

다음 페이지(P10-3)에서는 한 기계의 1X가 두 배가 된 가상 사례로, 자료에서 가설을 좁히고 확인 시험과 권고를 보고서로 잇습니다.
