# Roadmap — 전체 큰 그림

> 상태: **초안, 사용자 피드백 대기** · 작성 Claude · 2026-10-02 (커리큘럼 재구성, 2단계 마일스톤 반영. 같은 날 D-027: Part 0 진동 입문, 회전체 동역학 Part 4, Part 0~10, M0~M11)
> 무엇을 가르치나는 `Curriculum.md`, 페이지·랩 사양은 `Contents.md`, 진행 상황은 `Progress.md`에 있다.

## 1. 목표

1. 재구성한 커리큘럼(`Curriculum.md`, Part 0~10)을 언제든 다시 찾아볼 수 있는 **학습 사이트**로 만든다.
2. 신호처리는 읽는 페이지가 아니라 **조작해보는 실험실**로 만든다. 가상 신호를 만들고 샘플링 주파수, 분해능, 윈도우, 평균화를 바꾸면 결과가 바로 바뀌고, 수식에도 현재 값이 대입되어 보인다.
3. 만드는 과정도 학습이다. FFT, 윈도우, 보정계수를 직접 구현하고 해석해로 검증해서 상용 분석기가 내부에서 무엇을 하는지 체감한다 (D-009).

## 5. 인터랙티브 랩 설계 원칙

1. **참 신호 vs 측정 신호**: 연속 신호(선)와 샘플(점)을 언제든 겹쳐 그릴 수 있게 한다. 에일리어싱과 누설이 왜 생기는지 시간영역에서 보인다.
2. **한 파이프라인, 여러 프리셋**: 랩마다 계산을 새로 만들지 않는다. 같은 파이프라인에서 그 주제에 필요한 컨트롤만 노출한 것이 랩이다. 컨트롤을 전부 연 것이 샌드박스(LAB-SBX-01)다.
3. **살아있는 수식**: 식 옆에 현재 값을 대입한 결과를 보여준다. 예) Δf = F_max/LOR = 1000/3200 = 0.3125 Hz
4. **읽음값 vs 이론값**: 측정한 피크 주파수·진폭을 이론값과 표로 비교하고 오차(%)를 보여준다. 예) 입력 1.000 → Hann, bin 사이 정중앙 → 0.849 (−15.1 %)
5. **예측 → 확인 과제**: "이렇게 바꾸면 무엇이 보일까?"를 먼저 묻고, 조작해서 확인하게 한다.
6. **현장 프리셋**: 추상적인 숫자 대신 현장 상황(3600 rpm 발전기, 0.42X whirl, 기어 GMF ± 1X 등)을 버튼 하나로 불러온다.
7. **재현성**: 잡음은 시드 고정. (선택) 파라미터를 URL에 담아 실험 상태를 북마크한다.
8. **반응성 목표**: N ≤ 16384에서 슬라이더를 드래그하는 동안 끊김 없이 갱신한다 (requestAnimationFrame 스로틀, 필요하면 Web Worker).

## 6. 마일스톤 (2단계, D-017)

- **큰 마일스톤 `M{n}`** = 커리큘럼의 큰 범위 (대부분 Part 하나). 끝나면 그 범위의 페이지·랩이 모두 사이트에 있다.
- **세부 마일스톤 `M{n}.{m}`** = 실제 작업 단위. 한 에이전트가 한 세션 안에 끝내고, `main`에 커밋 하나로 사용자가 한 번에 확인할 수 있는 양 (대략 랩 1~2개, 또는 라이브러리 모듈 1개 + 테스트, D-019).
- 세부 목록은 계획이다. 큰 마일스톤을 시작할 때 담당자가 세부 목록을 다시 확인하고, 각 세부를 시작할 때 산출물과 완료 기준을 이 문서에 구체화한다.
- 번호 순서대로 진행한다. 같은 큰 마일스톤 안의 세부는 앞 번호에 의존할 수 있다.
- M 번호는 실행 순서라 Part 번호와 다르다: M1 = Part 1, M2 = Part 0, M3 = Part 2, M4 = Part 3, M5 = Part 4, M6~M11 = Part 5~10 (D-027).
- **2026-10-06부터 M1(트랙 A, Claude)과 M2(트랙 B, Antigravity)를 나란히 진행한다** (D-029). 두 트랙의 진행은 `Progress.md` 맨 위 트랙 현황 표에서 함께 본다.
