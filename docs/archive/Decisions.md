## D-013 마일스톤 순서: Phase 1 우선, 랩 단위 세분화
- 상태: **대체됨 → D-016** · 2026-10-02 · Claude
- 맥락: 사용자는 신호처리 인터랙션을 가장 중시하고, 커리큘럼도 Phase 1을 "가장 중요"로 둔다.
- 결정:
  - Phase 1을 M1~M5로 먼저, 절 단위로 나눠 만든다.
  - Phase 0은 Bode 랩이 필요하므로 M6에 둔다 (본문 글은 먼저 써도 된다).
  - Phase 3(필터·엔벨로프)을 Phase 4(결함 사전)보다 먼저 만든다. 베어링 랩이 엔벨로프를 쓰기 때문이다.
- 비고: 원본의 3개월 순서(2개월차 Phase 4 → 5 → 3)와는 다르다. 이 순서는 구현 의존성 기준이고, 학습 순서는 사이트에서 자유롭게 정하면 된다.

## D-016 마일스톤 계획 M0~M17 (Part 1 우선)
- 상태: **대체됨 → D-017** · 2026-10-02 · Claude
- 맥락: D-014로 커리큘럼 구조가 바뀌었다. 사용자는 신호처리 인터랙션을 가장 중시한다.
- 결정
  - M1~M7에서 Part 1(신호처리 기초)을 절 단위로 먼저 만든다. M7에서 샌드박스로 Part 1을 마무리한다.
  - 그다음 Part 0(M8) → Part 2(M9) → Part 3(M10~M11) → Part 4(M12) → Part 5(M13) → Part 6(M14) → Part 7(M15) → Part 8(M16) → Part 9(M17).
  - Part 0을 Part 1 뒤에 두는 이유: Part 0의 랩은 로터 모델과 Bode/오빗 플롯이 필요하고, Part 1의 공통 UI·플롯 위에 쌓는 편이 효율적이다. Part 0 본문 글은 먼저 써도 된다.
  - Part 3을 Part 5보다 먼저: 베어링·기어 진단 랩이 엔벨로프·TSA·켑스트럼을 쓴다.
- 대체: D-013
- 영향: `Roadmap.md` §6.
