## I-004 [콘텐츠] AF 반공진법 공식 표기
- 등록: 2026-10-02 · Claude
- 원본 (Phase 0 첫 과제): `AF = 1/(2ζ) = N1/(N2-N1)`
- 검토: Half-power법의 증폭계수는 `AF = N_c1/(N2 − N1)`이다. 분자는 임계속도(피크) N_c1이고, N1·N2는 피크 진폭의 0.707배가 되는 두 회전수다. 분자를 N1로 쓰면 AF가 작게 계산된다.
- 처리: 사이트에는 `N_c` 표기를 쓴다 (Contents §3, LAB-AF-01). 분리여유(Separation Margin) 요구식은 API 원문을 대조한 뒤 기재한다.
- 남은 일: API 684/617 원문 대조 (사용자 보유 자료 확인).

## I-005 [콘텐츠] 평균화 "랜덤 노이즈는 √N로 감소" 표현
- 등록: 2026-10-02 · Claude
- 원본 (1-4): Linear 평균에서 "랜덤 노이즈는 √N로 감소"
- 검토: 평균 방식에 따라 줄어드는 것이 다르다.
  - **RMS(파워) 평균**: 잡음 바닥의 *평균 레벨*은 그대로이고, 바닥의 *흔들림(표준편차)*만 1/√M로 줄어든다. 스펙트럼이 매끈해져서 읽기는 쉬워지지만 톤 대 잡음비 자체는 개선되지 않는다.
  - **벡터(트리거 동기) 평균, TSA**: 트리거와 동기되지 않은 잡음의 *진폭 자체*가 1/√M로 줄어든다. 톤 대 잡음비가 개선된다.
- 처리: LAB-AVG-01에서 두 방식을 나란히 보여주고 본문에서 구분한다 (Contents §5에 반영함).

## I-006 [콘텐츠] dB 기준값
- 등록: 2026-10-02 · Claude
- 원본 (1-5): "ISO ref 보통 1e-6 m/s or 1e-6 m/s²"
- 검토: ISO 1683의 진동 기준값은 속도 1 nm/s(1e-9 m/s), 가속도 1 µm/s²(1e-6 m/s²), 변위 1 pm으로 알고 있다. 업계에서는 VdB(예: 1e-8 m/s, 1e-6 in/s) 같은 다른 관례도 섞여 쓰인다.
- 처리: LAB-SPC-02에서 기준값을 선택할 수 있게 하고 출처를 표시한다. ISO 1683 원문을 확인한 뒤 확정한다.

## I-008 [콘텐츠] BSF 정의 관례 (1× / 2×)
- 등록: 2026-10-02 · Claude
- 원본 (4-2): `BSF = (D/2d)·fr·(1 − ((d/D)cosα)²)`
- 검토: 이 식은 볼의 자전 주파수다. 볼 결함은 한 번 자전할 때 내륜과 외륜을 모두 치므로 스펙트럼에서는 2×BSF가 두드러지는 경우가 많다. 문헌과 소프트웨어마다 BSF를 1× 또는 2×로 다르게 정의한다.
- 처리: LAB-BRG-01(P5-4, M6.4)에서 정의를 명시하고 1×와 2×를 모두 표시한다.

- 현상: `npm run dev`로 `/dev/math-plot/`를 열면 슬라이더·수식은 보이지만 그래프가 "불러오는 중…"에서 멈춤. 콘솔: `Error hydrating SineDemo.tsx — Failed to fetch dynamically imported module`, `katex.js?v=… 504 (Outdated Optimize Dep)`.
- 원인: 개발 서버가 켜진 상태에서 에이전트가 패키지 설치·`astro check`·`astro build`를 돌리면서 Vite 의존성 사전 번들 캐시(`node_modules/.vite`)를 다시 만들었다. 개발 서버가 들고 있던 버전과 캐시가 어긋나 KaTeX 모듈이 504 → 랩 컴포넌트 hydration 실패. 빌드본(`astro preview`)은 영향 없음.
- 처리 (`astro.config.mjs`)
  1. `vite.cacheDir`를 나눔: 개발 서버는 `node_modules/.vite`, build/check는 `node_modules/.vite-tasks` → 서로 덮어쓰지 않음
  2. `optimizeDeps.include`에 `katex`, `plotly.js-cartesian-dist-min` → 실행 중 새 의존성 발견으로 인한 재최적화 방지
  3. `Plot`: 라이브러리 로드 실패 시 "불러오지 못했습니다" 문구 표시 (무한 로딩 방지)
- 확인: 사용자 개발 서버에서 헤드리스 Edge로 플롯 렌더 확인. 그 뒤 `astro check`·`astro build`를 돌려도 개발 캐시 해시 불변, hydration 오류 0.
- 그래도 개발 화면이 깨지면: 개발 서버 재시작, 필요하면 `npm run dev -- --force` (캐시 재생성)
- **해결**: 2026-10-02

## I-019 [버그] 랩 hydration 불일치 (React 오류 #418)
- 등록: 2026-10-02 · Claude (M1.3)
- 현상: `/dev/lab-ui/`에서 콘솔에 `Minified React error #418` (hydration 중 텍스트 불일치).
- 원인: 랩 컴포넌트는 빌드 때 서버에서 한 번 그려지고 브라우저에서 다시 그려진다(hydration). 읽음값 표에 넣은 "계산 시간"(`performance.now`)이 서버와 브라우저에서 달라 불일치가 났다.
- 처리: 이런 값은 `useEffect`로 hydration이 끝난 뒤에만 보여준다. 규칙으로 AGENTS.md §6에 추가 — 시간, 시드 없는 난수, `window`·화면 크기처럼 서버와 브라우저에서 달라지는 값은 첫 렌더에 쓰지 않는다.
- **해결**: 2026-10-02 (오류 0건 확인)

## I-020 [환경] 헤드리스 브라우저에서 성능 측정이 0 ms로 나옴
- 등록: 2026-10-02 · Claude (M1.3)
- 현상: Edge 헤드리스 `--virtual-time-budget`으로 벤치마크를 돌리면 그리기 시간이 0 ms. `requestAnimationFrame`도 돌지 않아 측정이 멈춘다.
- 원인: 가상 시간 모드는 작업이 도는 동안 시계를 멈춘다. 헤드리스에는 화면 프레임이 없어 rAF가 오지 않을 수 있다.
- 처리: 실제 시간 측정은 Edge를 원격 디버깅 모드로 띄우고 `scripts/bench/plot-bench.mjs`(DevTools Protocol)로 한다. 벤치마크의 다음 단계 예약은 rAF 대신 `setTimeout`. 화면 캡처는 지금처럼 가상 시간 모드를 써도 된다.
- **해결**: 2026-10-02
