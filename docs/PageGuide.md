# PageGuide — 페이지 작성 지침서

> 이 사이트의 절 페이지(`P{Part}-{절}`)와 랩을 새로 쓰거나 고치는 **모든 작업자**(Claude, Codex, Antigravity)가 따르는 방법서다 (D-028).
> 기준 페이지는 **P1-0 ~ P1-4** — 사용자가 "마음에 든다"고 확인한 개편본이다 (2026-10-06). 애매하면 이 다섯 페이지를 열어 같은 상황을 어떻게 처리했는지 본다.
> 역할 분담: 무엇을 가르치나 = `Curriculum.md`, 어떤 개념을 어디서 처음 쓰나 = `Contents.md` §1-2(개념 척추), 랩 사양 = `Contents.md` §5, 기호 = `Contents.md` §3, 용어 = `Glossary.md`. 이 문서는 **어떻게 쓰나**만 다룬다.
> 결정 배경: D-025(톤), D-026(그림·상자·개념 순서), D-027(Part 0 독자 기준).

## 0. 한눈에 — 열 가지

1. **독자가 실제로 보게 될 장면이나 질문**으로 시작한다. 정의로 시작하지 않는다.
2. **앞 페이지까지 설명한 개념만** 쓴다. 처음 나오는 용어는 그 자리에서 한 줄로 푼다.
3. **개념 하나 = 그림 하나.** 랩을 만지지 않아도 그림과 캡션만으로 이해되어야 한다.
4. 그림 캡션은 "그림 n."으로 시작하고 **무엇을 보아야 하는지**를 문장으로 쓴다.
5. 랩 **앞**에는 따라 하기 상자(3~4단계, 구체적인 값과 질문), 랩 **뒤**에는 그 질문에 답하는 해석 문단.
6. 주장마다 **숫자**를 붙인다. 그 숫자는 그림·랩과 같은 계산에서 나온다.
7. 강조는 `Callout` 6종만. 이모지, 아스키 도표, 코드 블록은 페이지에 쓰지 않는다.
8. 말투는 화면을 같이 보며 짚어 주는 선배: "~합니다", "~해 보세요". 과장과 부정확한 비유는 쓰지 않는다.
9. "학교에서는 … 현장에서는 …" 같은 이분법을 쓰지 않는다. 앞 지식은 "P0-4의 공진"처럼 내용과 위치로 부른다.
10. 끝은 정리 표 → 확인 문제(답 숨김) → 다음 페이지 한 줄.

## 1. 독자와 목소리

### 1-1. 독자

| 범위 | 가정하는 것 | 가정하지 않는 것 |
|---|---|---|
| Part 0 | 고교 물리(F = ma), "미분 = 변화율" | 운동방정식, 고유진동수, 감쇠, 공진, 모드, 1X, 스펙트럼 |
| Part 1 이후 | Part 0을 읽었다 | 그 Part의 앞 페이지에 없는 신호처리 개념 |

독자는 사용자 한 사람이 아니다. 진동을 잘 모르는 사람이 읽어도 "이게 무슨 말이야?"가 나오지 않아야 한다 (I-022, I-023).

### 1-2. 말투

- 존댓말 평서체 "~합니다", 권유 "~해 보세요", 질문 "~일까요?"를 섞는다. 사전식 3인칭 정의("X란 ~이다. Y란 ~이다.")를 줄줄이 늘어놓지 않는다.
- 한 문단은 2~4문장, 한 문단에 한 생각. 핵심 문장 하나만 굵게.
- 목록은 3~5개. 그 이상이면 표로 바꾼다.
- 영문 병기는 처음 한 번만: `<strong>누설(Spectral Leakage)</strong>`. 이후에는 한글만.

### 1-3. 피할 표현과 바꿔 쓰기

| 피할 것 | 왜 | 이렇게 |
|---|---|---|
| "윈도우는 누설을 막는 마법" | 과장, 무엇을 하는지 없음 | "윈도우는 프레임 양 끝을 0 쪽으로 눌러, 경계에서 끊기는 곳을 없앱니다" |
| "파괴 에너지", "절대 표준", "치명적" | 과장 | 구체 숫자: "가속도로 보면 100배 커집니다" |
| "학교에서는 MCK로 배웠지만 현장에서는…" | 이분법 (D-025) | "P0-4의 공진이 기동 중에는 이렇게 보입니다" |
| "작은 성분", "충분히 길게" | 기준 없음 | "잡음 바닥(0.03 mm/s)보다 작은 0.018 mm/s 성분", "10초 (Δf 0.1 Hz)" |
| "당연히", "쉽게 알 수 있듯이" | 모르는 독자를 밀어냄 | 빼거나 이유를 한 줄 쓴다 |
| 물리적으로 틀린 비유 | 오개념을 심음 | 비유를 빼는 편이 낫다 |

## 2. 개념 순서 (가장 중요)

1. 페이지는 **앞 페이지까지 설명한 개념만** 쓴다. 기준표는 `Contents.md` §1-2 개념 척추, 용어별 첫 위치는 `Glossary.md`.
2. 뒤에서 다룰 개념이 꼭 필요하면 한 줄로 풀고 위치를 밝힌다.
   - 예: "메인로브(성분 자리의 가운데 봉우리, P1-4에서 자세히)"
3. 진단 용어를 예로 쓸 때도 한 줄로 푼다. 풀기 어려우면 예로 쓰지 않는다.
   - 예: "2LF(전원 주파수의 2배, 60 Hz 전력망이면 120 Hz)"
4. 앞 페이지에서 설명한 개념은 길게 다시 풀지 않고 위치만 밝힌다.
   - 예: "P1-0에서 RMS가 '제곱 평균의 제곱근'이었습니다", "고유진동수(P0-2)"
5. 새 용어를 쓰면 `Glossary.md`에 한 줄 추가한다 (페이지 순서에 맞는 자리에).

**스스로 점검하는 법**: 다 쓴 페이지에서 굵은 글씨와 기호를 모두 뽑아, 하나씩 "이 페이지에서 풀었나, 앞 페이지에 있나"를 Glossary로 확인한다.

### 3-2. 절의 리듬

한 절(`##`)은 이 순서를 따른다. 절 사이에는 `---`를 둔다.

1. **질문**: 이 절이 답할 물음 한두 문장
2. **그림**: 그 개념을 보여 주는 `Figure`
3. **설명**: 그림에서 읽을 것을 짚고, 필요하면 식 → 기호 풀이 → `example` 상자로 숫자 대입
4. (랩이 있으면) **따라 하기 → 랩 → 해석**
5. **함정**: 흔한 오해 하나를 `warn` 상자로

### 3-3. 제목 짓기

- `##` 제목은 "주제: 한 줄 결론" 또는 질문형. 제목만 이어 읽어도 페이지 줄거리가 보여야 한다.
  - P1-5: "파워 평균: 매끈해지지만 낮아지지는 않는다" · "벡터 평균: 위상까지 평균하면 잡음이 지워진다"
  - P1-3: "왜 오래 재야 하나: Δf = 1/T" · "오래 잴 수 없을 때: 스미어링"
- `###`는 한 절 안의 단계 ("1.1 FFT는 프레임이 되풀이된다고 본다", "1.2 스펙트럼에서 보면: 퍼지고, 낮아진다").

### 3-4. 분량 (P1-0 ~ P1-5 기준)

| 항목 | 범위 | 비고 |
|---|---|---|
| MDX 줄 수 | 240 ~ 400 | 길어지면 절을 나누기보다 설명을 줄인다 |
| `##` 절 | 6 ~ 9 (정리·확인 문제 포함) | |
| 그림 | 5 ~ 10 | 개념마다 하나 |
| 랩 | 1 ~ 4 | 미니 랩도 좋다 (P1-0의 LAB-BAS-01·02) |
| 확인 문제 | 5 ~ 7 | 계산 + 판단 섞기 |
| 상자 | 페이지당 8 ~ 15 | 한 절에 3개를 넘기지 않는다 |

**글 · 그림 · 랩의 비율**: 그림 없이 글만 한 화면(약 25줄)을 넘기지 않는다. 랩이 설명을 대신하지 않는다 — 랩은 그림으로 이해한 것을 손으로 확인하는 자리다 (사용자 피드백: "조작하는 것과 텍스트·그림 비율이 안 맞는다").

## 4. 도입과 마무리

### 4-1. 도입

독자가 실제로 마주칠 화면이나 생활 속 장면에서 출발한다. 짧게.

> 스펙트럼 바닥에 작은 막대 하나가 보일 듯 말 듯합니다. 다시 재면 사라지고, 또 재면 엉뚱한 곳에 비슷한 막대가 섭니다. 진짜 성분일까요, 잡음이 우연히 튄 걸까요? — P1-5

> 진동 분석기를 처음 켜면 화면에 이런 것들이 한꺼번에 나타납니다. (목록 3개) 이 페이지의 목표는 이 화면을 한 줄씩 읽을 수 있게 되는 것입니다. — P1-0

Part 0은 `Curriculum.md` 각 절의 "여는 질문"을 쓴다 (예: 책상 끝에 눌러 놓은 자를 튕기면 왜 한동안 계속 떨릴까?).

### 4-2. "이 페이지를 다 읽으면" (`idea` 상자)

4~5개, "~할 수 있다 / ~를 안다"로 끝나는 번호 목록. 페이지의 `##` 절과 대략 하나씩 대응한다.

### 4-3. 정리 표

```mdx
| 주제 | 꼭 기억할 것 |
|---|---|
| 파워 평균 | 평균 높이는 그대로, 흔들림만 $1/\sqrt{M}$. 바닥보다 작은 성분은 안 드러난다 |
```

5~7행. 판단을 돕는 표("하려는 일 | 고를 것 | 함께 확인할 것")를 따로 둬도 좋다 (P1-5 §6).

### 4-4. 확인 문제

```mdx
<details>
<summary><strong>Q1. 두 프레임에서 같은 bin의 진폭이 1과 3 mm/s RMS였습니다. 파워 평균의 표시 진폭은?</strong></summary>

$(1^2 + 3^2)/2 = 5$ (mm/s)², 제곱근을 취해 $\sqrt{5} \approx 2.24$ mm/s RMS입니다. 진폭의 단순 평균 2가 아닙니다.
</details>
```

- 계산 문제(숫자 답)와 판단 문제("보고해도 되나요?", "무엇일 가능성이 큰가요?")를 섞는다.
- 답에는 숫자와 **이유**를 쓴다. 흔한 오답이 왜 틀렸는지 한 줄 붙이면 더 좋다.

### 4-5. 다음 페이지로

한 문장: "다음 페이지(P1-6)에서는 …을 다룹니다." Part 0은 각 절의 **Part 1 연결**(Curriculum의 "Part 1 연결" 항목)을 이 자리나 마지막 절에 쓴다.

## 5. 그림 (`Figure`)

### 5-1. 원칙

- 설명하는 개념마다 그림 하나. 조작하지 않아도 그림만 보고 이해되어야 한다.
- 그림의 숫자는 본문 숫자와 **같은 계산**에서 나온다. 그래서 그림 데이터는 손으로 적지 않고 `lib/dsp`(Part 1)·`lib/mck`(Part 0)로 계산한다.
- 본문은 그림을 "그림 n"으로 부르고, 그림 바로 뒤에서 **읽을 것**을 짚는다:

  > 그림 1에서 읽을 수 있는 것:
  > - **세로로 얼마나 크게 출렁이나** → 진동의 크기
  > - **같은 모양이 얼마나 자주 되풀이되나** → 진동의 빠르기 (0.1초에 6번 → 1초에 60번)

### 5-2. 만드는 법

1. `src/figures/p{Part}-{절}.ts`에 `export const 이름: FigureSpec = { id, caption, panels }`를 쓴다. 형식은 `src/lib/figure.ts`.
2. 페이지에서 `import * as F from '../figures/p0-1';` → `<Figure {...F.이름} />`.
3. `/dev/figures/` 갤러리(`src/pages/dev/figures.mdx`)에 그 파일을 등록하고 빌드해서 겹침·잘림을 본다.

- **id**: `fig-p{Part}-{절}-{n}` (예: `fig-p0-1-1`). 갤러리에서 모든 그림이 한 페이지에 모이므로 겹치면 안 된다. (기존 Part 1 그림은 `fig-1-2` 같은 옛 형식을 그대로 둔다.)
- **캡션**: "그림 n."으로 시작. 무엇을 그렸는지(조건 포함) → 무엇을 보아야 하는지 → 그래서 무엇을 알 수 있는지. 캡션 속 숫자는 계산값을 `formatNumber`로 넣는다.
- **패널**: 세로로 쌓인다. 높이 100 ~ 220 (680 폭 기준 값, 실제는 ×1.2). 한 그림에 패널 1 ~ 4개.
- **내부 단위**: 계산은 SI, 그림에 넣을 때만 mm/s·µm 등으로 바꾼다 (D-012).

### 5-3. 색과 표기

| 색 | 쓰임 | 캡션에서 부르는 이름 |
|---|---|---|
| `c1` | 주인공 신호 | 파랑 |
| `c2` | 비교 대상, 두 번째 신호 | 주황 |
| `c3` | 세 번째, "좋은 쪽" 결과 | 초록 |
| `c4` | 네 번째 | 보라 |
| `warn` | 주목할 점·목표 성분·위험선 | 주황(갈색 주황) — c2와 한 그림에 같이 쓰지 않는다 |
| `muted` | 기준선, 평균선, 포락선, 배경 | 회색 |

- 캡션의 색 이름과 실제 색이 맞아야 한다.
- dB 스펙트럼은 `stem`이 0 dB에서 내려와 보기 나쁘므로 선 + 점(`line` + `dots`)으로 그린다.
- 겹쳐 그리는 선이 셋을 넘으면 패널을 나눈다.

### 5-4. 도식 그림 (질량·스프링·원판 — Part 0)

축 없는 패널에 기계 그림을 그린다. 견본: `src/figures/dev-schematic.ts` (갤러리 맨 아래 "도식 견본").

- 패널에 `frame: false`를 주면 축·격자·눈금이 사라진다.
- `y: { range: squareYRange(x범위, height) }`로 x·y 축척을 같게 한다 (원이 찌그러지지 않게).
- 도형 주석: `ground`(벽·바닥 빗금, `side`로 빗금 방향) · `spring`(`coils`, `label`) · `damper` · `rect`(질량, `label`) · `arrow`(힘·변위, `double: false`) · `line`(기준선, `dash`) · `circle`(반지름 px, `fill`) · `point` · `text`.
- 도식 패널 아래에 같은 계의 응답 그래프 패널을 붙이면 "그림 → 움직임"을 한 그림에서 보여 줄 수 있다.
- 움직이는 그림(애니메이션)은 그림이 아니라 랩으로 만든다 (§6-4).

### 5-5. 그림 숫자 회귀 테스트

본문이 그림의 숫자를 인용하면("70 Hz 막대는 0.0495 mm/s"), 그 값을 테스트로 고정한다. 예: `src/figures/figures-p1-4-5.test.ts`. 계산 코드를 고쳤을 때 본문과 그림이 어긋나는 것을 막는다.

### 6-1. 강조 상자 (`Callout` 6종)

|---|---|---|---|
| `idea` | 핵심 | 페이지 첫머리 "이 페이지를 다 읽으면". 그 밖에는 아주 드물게 | 이 페이지를 다 읽으면 |
| `term` | 용어 풀이 | 새 용어를 처음 쓸 때 (2~4문장, 영문 병기) | 랜덤 잡음 (Random Noise) |
| `example` | 숫자 예 | 식에 숫자를 넣어 단계별로 계산 | 진폭 1과 3을 파워 평균하면 |
| `try` | 따라 하기 | **랩 바로 앞**의 조작 순서 | (제목 없이) |
| `warn` | 주의 | 흔한 오해·실수 하나. 제목에 오해를 따옴표로 | '매끈해졌다'와 '바닥이 낮아졌다'는 다르다 |
| `field` | 현장에서는 | 실제 측정·장비에서 어떻게 나타나는지, 뒤 Part와의 연결 | 회전 각도에 맞춰 평균하기 (TSA) |

- 상자 안 마크다운은 여는 태그 뒤, 닫는 태그 앞에 **빈 줄**을 둔다.
- `title` 속 따옴표는 작은따옴표(`'`)만 쓴다.

### 6-2. 따라 하기 → 랩 → 해석

```mdx
<Callout type="try">

1. 처음 상태(파워 평균, M = 64, 오버랩 0 %)에서 "전체 결과 보기"를 누릅니다.
2. M을 1 → 4 → 16 → 64로 바꿉니다. 70 Hz 막대가 언제부터 또렷해지나요? 32 Hz는요?
3. 아래 두 그래프에서 바닥의 평균 높이가 1 근처에 머무는지 봅니다.
4. 잡음 크기 σ를 0으로 내립니다. 읽음값이 이론값(0.0495, 0.0177 mm/s)과 맞는지 확인합니다.

</Callout>

<AveragingLab client:visible />

2번에서 70 Hz는 몇 번만 평균해도 … 서지만, 32 Hz는 64번을 평균해도 … 4번처럼 잡음을 없애면 …
```

- 단계는 3~4개. 각 단계는 **무엇을 어떤 값으로 바꾸고 무엇을 보는지**를 말한다. 시작 상태를 첫 단계에 밝힌다.
- 해석 문단은 "2번에서 …", "4번처럼 …"으로 따라 하기의 질문에 **숫자로** 답한다.
- 예상과 다른 결과가 나올 수 있으면(반올림, 잡음 한 번의 우연 등) 미리 말해 둔다.

### 6-3. 랩을 페이지에 넣는 법

- 랩은 개념 설명과 그림 **바로 뒤**에 둔다. 페이지 끝에 몰아 두지 않는다.
- 같은 랩을 여러 절에서 쓰면 props로 시작 상태를 바꾸고 `client:visible`로 넣는다 (P1-5의 `initialMode`, `initialScenario`, `initialCount`). 한 번만 쓰는 랩은 `client:load`도 된다.
- 랩 사양은 `Contents.md` §5에 먼저 쓴다 (목적·신호·조작·출력·수식·과제·검증).

### 6-4. 랩 컴포넌트

- `LabFrame`으로 감싸고, 입력은 `ParamSlider`·`ParamSelect`·`ParamToggle`, 읽음값은 `ReadoutTable`, 수식은 `Formula`, 플롯은 `Plot`만 쓴다 (극좌표 Polar는 `PolarPlot`, D-035 — 예: P2-3의 `PhaseLab`·`SlowRollLab`). 예시: `/dev/lab-ui/` (`LabUiDemo.tsx`).
- 구조: 조작 → 플롯 → 수식(현재 값 대입) → 읽음값(측정값 vs 이론값) → 실험 과제(질문 + 접힌 답).
- 프리셋·라벨·과제에도 풀지 않은 전문용어를 쓰지 않는다.
- 계산은 `lib/`의 순수 함수로. 본문 그림과 같은 신호·시드를 쓰면 그림과 랩의 숫자가 일치한다. 그림과 랩이 같이 쓰는 신호는 한 파일에 둔다 (예: `src/lib/gearbox.ts`).
- `Plot` 색은 `'var(--plot-1)'`처럼 CSS 변수로 주면 라이트·다크 테마를 따른다 (래퍼가 실제 색으로 풀어 준다). 색을 주지 않은 계열은 **계열 순서대로** `--plot-1`, `--plot-2` …를 받으므로, 앞 계열(참값·기준선)에만 회색을 주면 뒤의 주인공 계열이 주황이 된다 → 주인공 계열에도 색을 적는다. 그림(`Figure`)과 같은 색 약속(§5-3)을 쓴다.
- **서버에서 한 번 그려진다** (hydration, I-019): 첫 렌더에 시간(`performance.now`), 시드 없는 난수, `window`·화면 크기를 쓰지 않는다. 애니메이션은 정지 상태로 그려 두고, `useEffect` 안에서 `requestAnimationFrame`으로 재생 버튼을 눌렀을 때 움직인다. 이론상 0인 값의 부동소수점 찌꺼기(1e-15)는 0으로 표시한다.

## 7. 수식과 숫자

- 식 앞에 말로 먼저 설명하고, 식 바로 뒤에 기호를 한 줄로 푼다: "$S_{m,k}$는 $m$번째 프레임, $k$번째 bin의 파워, $M$은 평균한 프레임 수입니다."
- 기호·식의 표기는 `Contents.md` §3이 단일 기준이다. 정현파는 $x(t) = A\cos(2\pi f t + \varphi)$ (위상은 `\varphi`).
- 숫자 예는 `example` 상자에 단계별로 쓴다 ("1. 제곱한다 … 2. 평균한다 … 3. 되돌린다 …").
- 단위와 표기를 붙인다: "0.0495 mm/s RMS", "50 µm p-p". Peak인지 RMS인지 늘 밝힌다.
- 랩·그림에서 숫자를 문자열로 만들 때 `texNumber(v, sig)`·`formatNumber(v, sig)`의 둘째 인자는 **유효숫자**다 (소수 자리 아님). 주파수·dB는 3~4. 아주 작은 값은 지수 표기가 되므로 캡션에서는 `toFixed`가 나을 때가 있다.

## 8. MDX 함정

| 증상 | 원인 | 처방 |
|---|---|---|
| 굵은 글씨가 `**…**` 그대로 보임 | 문장부호로 끝나는 굵은 글씨 바로 뒤에 한글 | `<strong>…</strong>` |
| 표가 깨짐 | 표 안 수식에 `|` | `\lvert x \rvert` |
| 빌드 오류 | 본문에 `{`, `<` | 수식 안에 넣거나 말로 바꾼다 |
| 수식 속 한글이 깨짐 | KaTeX 한글 | `\text{한글}` |
| 상자 안 목록·수식이 안 그려짐 | 여는/닫는 태그와 내용 사이에 빈 줄 없음 | 빈 줄 추가 |
| 아래첨자 깨짐 | KaTeX 버전 둘 | `npm ls katex` (I-021) |
| 랩 첫 화면이 깜빡이거나 React 오류 #418 | 서버·브라우저 첫 렌더 불일치 | §6-4 |
| 랩 SVG 안 글자(값)가 안 보임 | SVG `<text>` 안에 HTML `<strong>` | `<tspan fontWeight="bold">` (P0-6, 2026-10-06) |
| 도식의 원이 점으로 보이거나 안 보임 | `circle`의 `r`는 **px** 단위 (x 단위가 아님) | `r: 반지름 × (820 / x 범위 폭)` (§5-4, P0-6) |

## 10. Part 0 특기 사항

- **독자 기준**: 고교 물리와 "미분 = 변화율"만. 미분 기호 $\dot x$, $\ddot x$는 처음 쓸 때 "변위가 변하는 빠르기(속도)", "속도가 변하는 빠르기(가속도)"로 푼다.
- **식은 말 다음에**: "무엇이 무엇을 정하나"를 말로 먼저("무거우면 느리고 단단하면 빠르다") 하고 식($f_n = \sqrt{k/m}/2\pi$)을 쓴다.
- **스펙트럼은 아직 없다**: Part 0은 Part 1보다 앞이다. bin, $f_s$, FFT, 윈도우는 쓰지 않는다. 주파수 축 위에 줄을 세우거나(P0-7, LAB-FMAP-01) 막대 스펙트럼을 미리 보여 줄 때는(P0-8, LAB-SRC-01) "성분마다 크기를 막대로 세운 그림(P1-0에서 자세히)"처럼 푼다.
- **Part 1 연결**: 각 절은 Part 1의 어느 내용으로 이어지는지 밝히며 끝난다 (`Curriculum.md` 각 절의 "Part 1 연결").
- **그림**: 개념마다 도식(§5-4) + 응답 그래프. 질량-스프링 그림의 방향·부호(오른쪽이 +, 평형 위치 점선)를 페이지 사이에서 통일한다.
- **랩**: Part 0 랩은 미니 랩이다 (조작 2~4개). 질량이 움직이는 애니메이션은 랩에서 SVG로 그리고 §6-4의 hydration 규칙을 지킨다. 계산은 `lib/mck`의 순수 함수.
- **용어 일치**: 정현파·진폭·주파수·위상·1X 등은 지금 P1-0이 설명하고 있다. Part 0에서 먼저 설명하게 되므로, 같은 뜻·같은 기호로 쓰고 `Glossary.md`의 "처음 나오는 곳"을 P0 쪽으로 고친다. P1-0 본문 정리는 M2.8에서 한다.
