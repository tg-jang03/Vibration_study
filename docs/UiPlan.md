# UI 개편 계획

2026-10-08 · Codex · 제안 (D-048)

공학 학습서와 계측 도구의 분위기로 개편한다. 글·수식·그래프의 중요도가 먼저 드러나고, 학습 위치와 실험 조작 방법을 쉽게 찾는 화면을 목표로 한다. 이번 세션은 방향과 틀을 정리한다. 구현 담당과 세부 일정은 다음 작업에서 정한다.

## 디자인 원칙

- 흰 바탕과 짙은 글자, 차분한 파란 강조색을 기본으로 삼는다. 다크 모드도 같은 정보 위계를 따른다.
- 글과 목차는 여백·글자 크기·구분선으로 묶는다. 상자는 실험 조작부와 주의사항 등 경계가 필요한 곳에 쓴다.
- 둥근 버튼·색 면적·배지·숫자 통계를 줄인다. 모서리는 4~6px부터 검토한다.
- 그래프 계열의 색은 데이터 구별에 쓴다. 파형·스펙트럼·도식이 화면의 중심이 되게 한다.
- 재생 애니메이션은 물리 현상을 설명할 때 쓴다. 장식용 이동·확대 효과는 줄인다.

## 화면 구성

| 화면 | 위에서 아래로 배치 | 핵심 변화 |
|---|---|---|
| 홈 | 사이트 이름과 메뉴 → 짧은 소개와 처음부터/이어서 보기 → 대표 실험 하나 → 4단계 학습 목차 → 랩·레퍼런스 바로 가기 | 통계 카드·진행률 원을 덜어내고, Part를 구분선으로 나눈 행으로 표시한다. 제목·다루는 질문·절 링크가 읽히게 한다. |
| 본문 | 왼쪽 학습 목차 / 오른쪽 제목·짧은 도입·학습 목표 → 설명·수식·그림·실험 → 정리·문제·참고자료·다음 절 | 학습 목표는 짧은 목록, 보충 설명은 작은 제목과 선으로 구분한다. 주의사항은 눈에 띄게 남긴다. |
| 랩 | 제목과 원문 링크 → 왼쪽 조작부 / 오른쪽 주 그래프 → 주요 값·수식 → 따라 하기·결과 해석 | 조작부와 그래프의 관계를 가깝게 둔다. 여러 그래프는 비교 목적에 맞게 정렬하고 반복 제목·중첩 테두리를 줄인다. |
| 랩 모음·레퍼런스 | 제목 → 검색·필터 → 항목 목록 → 상세 내용 | 긴 항목은 제목·설명·링크를 정렬한 목록으로 만든다. 필터 선택 상태가 분명하게 보이게 한다. |

홈의 대표 실험은 기존 랩 한 개의 핵심 조작과 그래프를 활용한다. 기본 상태는 정지이며 전체 랩으로 이동할 수 있다. 내용과 동작이 겹치는 새 계산기를 추가하지 않는다.

Part·절의 제작 상태와 사용자의 학습 진행을 구별한다. 제작 완료율을 학습 진도로 표현하지 않는다. 읽을 수 있는 절과 준비 중인 절은 목차에서 구별한다.

## 공통 스타일의 시작값

| 항목 | 시안의 기준 |
|---|---|
| 색 | 바탕 #ffffff, 글자 #202428, 보조 글자 #626b75, 강조 #244e6e, 선 #dce1e6 |
| 글자 | 한글 본문 17px 안팎, 줄 간격 1.75~1.8. 제목은 크기와 굵기로 위계를 만든다. |
| 폭 | 기존 본문·그림·랩의 920px 폭 원칙을 이어간다. 넓은 화면에서 왼쪽 목차와 본문을 함께 배치한다. |
| 구분 | 일반 목록은 선과 여백, 조작부는 옅은 배경, 주의사항은 명확한 색과 제목을 쓴다. |
| 버튼 | 주 동작 하나를 강조하고 보조 이동은 간결한 링크로 표시한다. |

색·수치는 시안의 시작값이다. 대비와 그래프 가독성을 확인하면서 조정한다. 좁은 화면은 목차를 접고 조작부를 그래프 위로 쌓으며 가로 넘침을 점검한다.

## 적용 순서

1. **대표 화면 시안**: 홈·P1-2·LAB-BAS-01을 같은 스타일로 구성해 전체 인상과 읽기 편한 정도를 확인한다. 큰 개편에 앞서 이 시안을 사용자와 검토한다.
2. **공통 스타일과 홈**: 색·글자·간격·버튼·헤더를 정리하고 홈 목차를 적용한다. 주요 파일은 `global.css`, `BaseLayout`, `index.astro`다.
3. **본문과 탐색**: `MdxLayout`·내용 컴포넌트·Part 목차·레퍼런스에 적용한다. Callout 6종의 의미와 Figure·수식·인용 기능을 유지하면서 시각적 강조를 조정한다.
4. **랩과 목록**: `LabFrame`·매개변수 UI·값 표를 정리하고, 단순 파형·여러 그래프·오빗/Polar·색 지도 랩에서 확인한 뒤 전체로 확장한다.

공용 파일과 홈을 다루므로 구현 담당 한 명이 통합한다. 기존 A/B 소유 규칙과 맞출 담당·세부 작업은 구현 착수 때 정한다. 이번 계획으로 콘텐츠 마일스톤의 배정을 바꾸지 않는다.

## 완료 기준

- 홈에서 읽기 시작·이어서 보기·원하는 Part·랩을 바로 찾을 수 있다.
- 본문에서 핵심 그림과 보조 안내의 중요도 차이가 보이고, 긴 페이지에서도 학습 위치를 알 수 있다.
- 랩에서 변경할 값과 결과 그래프를 함께 확인하며 기존 재생·초기화·수식·원문 이동이 동작한다.
- 계산 함수·수치·교육 순서는 유지한다. 주소와 내부 링크는 기존 `withBase()` 규칙을 따른다.
- 구현 단계마다 check·test·build와 verify:links를 통과한다. preview에서 기존 verify:page로 홈·대표 본문·랩·목록을 점검하고, 필요한 기존 smoke 옵션으로 조작을 확인한다.
