## D-006 정적 사이트, 브라우저 내 계산
- 상태: 제안 · 2026-10-02 · Claude
- 맥락: 개인 학습용이고 사용자는 1명이다. 다룰 신호 크기(N ≤ 16384)는 브라우저에서 실시간으로 충분히 계산할 수 있다.
- 결정: 서버 없는 정적 사이트로 만들고 모든 계산은 브라우저에서 한다.
- 호스팅: GitHub Pages가 1순위 후보. 단, GitHub 무료 계정은 **공개 저장소**에서만 Pages를 쓸 수 있다. 저장소를 비공개로 두려면 GitHub Pro를 쓰거나 Cloudflare Pages·Netlify 같은 대안을 쓴다. I-003에서 함께 결정한다.
- 대안:
  - Python 서버(Streamlit/Dash) → 호스팅이 필요하고 슬라이더 반응이 느려서 기각.
  - Pyodide(브라우저 Python) → 초기 로딩이 수십 MB라 기각.
  - Jupyter 노트북 → 인터랙션은 좋지만 "웹페이지" 목표와 다르다. 대신 numpy 교차검증 스크립트는 `scripts/verify/`에 허용.

## D-007 Astro + MDX + React + TypeScript
- 상태: 제안 · 2026-10-02 · Claude
- 맥락: 사이트 대부분은 글과 수식이고, 일부가 계산이 많은 인터랙티브 위젯이다.
- 결정: Astro(정적 생성) + MDX(본문에 수식과 랩 컴포넌트를 섞어 씀) + React island(랩) + TypeScript(strict). 패키지 매니저는 npm, 테스트는 Vitest.
- 대안:
  - Vite + React SPA → 콘텐츠 페이지 관리와 수식 본문 작성이 번거롭다.
  - Next.js → 이 프로젝트에 필요 없는 서버 기능이 많다.
  - Svelte → 두 에이전트 모두 React 생태계가 더 익숙하다.
- 영향: Node.js 설치 필요 (I-001).

- 대안: fft.js 같은 라이브러리 → 학습 효과가 줄어 기각. 성능 문제가 확인되면 FFT 부분만 교체할 수 있다 (새 결정 필요).

## D-010 플롯: Plotly.js (래퍼로 격리)
- 상태: 제안 (M1 프로토타입 후 확정) · 2026-10-02 · Claude
- 결정: Plotly.js 부분 번들로 시작하고, 모든 랩은 `components/ui/Plot` 래퍼만 사용한다. 필요한 trace 종류가 생기면 번들을 늘린다.
- 이유: 선, 막대, 히트맵(스펙트로그램·Kurtogram), 등축 X-Y(오빗)를 한 라이브러리로 해결하고 줌·호버가 기본 제공된다.
- 대안: uPlot → 매우 빠르지만 히트맵이 약하다. 직접 Canvas 구현 → 시간이 너무 든다. M1에서 슬라이더 드래그 성능이 부족하면 시간·스펙트럼 플롯만 uPlot으로 바꾼다. 래퍼 덕분에 랩 코드는 바뀌지 않는다.

## D-011 신호 모델: 해석적 성분의 합
- 상태: 제안 · 2026-10-02 · Claude
- 결정:
  - 가상 신호 `SignalSpec`은 해석적 성분(정현파, 하모닉 열, AM/FM, 감쇠 임펄스열, 처프/런업, 잡음)의 합이다.
  - 임의의 시간 t에서 계산할 수 있으므로 "참 신호"는 고해상도로 그리고, 샘플링은 t = n/f_s에서 평가한다.
  - 잡음은 시드 고정 난수로 만든다.
  - AAF: 결정론적 성분에는 주파수별 필터 이득·위상을 해석적으로 곱한다. 잡음은 높은 배율로 오버샘플해서 만든 뒤 디지털 필터 → 데시메이션한다.
- 이유: 에일리어싱을 "참 vs 측정"으로 정확히 보여줄 수 있고, 테스트 기대값을 해석적으로 계산할 수 있다.

## D-012 단위계: 내부 SI
- 상태: 제안 · 2026-10-02 · Claude
