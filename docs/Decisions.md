## D-006 정적 사이트, 브라우저 내 계산
- 상태: 제안 · 2026-10-02 · Claude
- 맥락: 개인 학습용이고 사용자는 1명이다. 다룰 신호 크기(N ≤ 16384)는 브라우저에서 실시간으로 충분히 계산할 수 있다.
- 결정: 서버 없는 정적 사이트로 만들고 모든 계산은 브라우저에서 한다.
- 호스팅: GitHub Pages가 1순위 후보. 단, GitHub 무료 계정은 **공개 저장소**에서만 Pages를 쓸 수 있다. 저장소를 비공개로 두려면 GitHub Pro를 쓰거나 Cloudflare Pages·Netlify 같은 대안을 쓴다. I-003에서 함께 결정한다.
- 대안:
  - Python 서버(Streamlit/Dash) → 호스팅이 필요하고 슬라이더 반응이 느려서 기각.
  - Pyodide(브라우저 Python) → 초기 로딩이 수십 MB라 기각.
  - Jupyter 노트북 → 인터랙션은 좋지만 "웹페이지" 목표와 다르다. 대신 numpy 교차검증 스크립트는 `scripts/verify/`에 허용.

  - Next.js → 이 프로젝트에 필요 없는 서버 기능이 많다.
  - Svelte → 두 에이전트 모두 React 생태계가 더 익숙하다.
- 영향: Node.js 설치 필요 (I-001).

## D-010 플롯: Plotly.js (래퍼로 격리)
- 상태: **확정** (사용자 2026-10-02, M1.3 실측 근거) · 제안 Claude
- 결정: Plotly.js 부분 번들로 시작하고, 모든 랩은 `components/ui/Plot` 래퍼만 사용한다. 필요한 trace 종류가 생기면 번들을 늘린다.
- 이유: 선, 막대, 히트맵(스펙트로그램·Kurtogram), 등축 X-Y(오빗)를 한 라이브러리로 해결하고 줌·호버가 기본 제공된다.
- 대안: uPlot → 매우 빠르지만 히트맵이 약하다. 직접 Canvas 구현 → 시간이 너무 든다. M1에서 슬라이더 드래그 성능이 부족하면 시간·스펙트럼 플롯만 uPlot으로 바꾼다. 래퍼 덕분에 랩 코드는 바뀌지 않는다.
- 갱신 (2026-10-02, M1.3): 실측 (헤드리스 Edge, SVG scatter, 30회 갱신) — N=1024 평균 7.6 ms, N=4096 평균 9.4 ms (최대 16.8 ms), N=16384 평균 12.9 ms (최대 28.4 ms). 60 fps 예산(16.7 ms) 안이므로 Plotly 유지를 **확정 제안**. 사용자가 확인하면 상태를 `확정`으로 바꾼다.

## D-011 신호 모델: 해석적 성분의 합
- 상태: 제안 · 2026-10-02 · Claude
- 결정:
  - 가상 신호 `SignalSpec`은 해석적 성분(정현파, 하모닉 열, AM/FM, 감쇠 임펄스열, 처프/런업, 잡음)의 합이다.
  - 임의의 시간 t에서 계산할 수 있으므로 "참 신호"는 고해상도로 그리고, 샘플링은 t = n/f_s에서 평가한다.
  - 잡음은 시드 고정 난수로 만든다.
  - AAF: 결정론적 성분에는 주파수별 필터 이득·위상을 해석적으로 곱한다. 잡음은 높은 배율로 오버샘플해서 만든 뒤 디지털 필터 → 데시메이션한다.
- 이유: 에일리어싱을 "참 vs 측정"으로 정확히 보여줄 수 있고, 테스트 기대값을 해석적으로 계산할 수 있다.

## D-022 Flat top 윈도우 계수 정의 선택 (I-010)
- 상태: 제안 · 2026-10-02 · Antigravity
- 맥락: Flat top 윈도우는 여러 계수 정의(MATLAB `flattopwin`, Heinzel 2002 HFT 계열, ISO 18431-2 등)가 존재하며 정의마다 대역폭(ENBW)과 스캘럽 손실이 달라 단일 표준을 정해야 했다 (I-010).
- 결정: ISO 18431-2, SciPy(`scipy.signal.windows.flattop`), MATLAB(`flattopwin`), D'Antona & Ferrero (2006)에서 널리 쓰이는 표준 5항 코사인 정의를 채택한다.
  - 형태: $w[n] = a_0 - a_1\cos(2\pi n/N) + a_2\cos(4\pi n/N) - a_3\cos(6\pi n/N) + a_4\cos(8\pi n/N)$
  - 계수: $a = [0.21557895, 0.41663158, 0.277263158, 0.083578947, 0.006947368]$
  - 특성: CG ≈ 0.2156, ACF ≈ 4.639, ECF ≈ 2.389, ENBW ≈ 3.77 bin (≈ 3.8 bin), 스캘럽 손실 < 0.01 dB (≈ 0.005 dB), 메인로브 ±5 bin
- 대안: Heinzel 2002의 HFT70/90D 등. 범용 분석기 및 Python/MATLAB 생태계와의 호환성을 고려해 ISO/SciPy/MATLAB 표준을 선택함.

  5. **진행 기록** (`Progress.md`): 맨 위 **트랙 현황 표**에서 두 트랙의 담당·지금 세부·상태를 한눈에 본다. 핸드오프와 세션 로그는 트랙별 절로 나눈다(같은 줄에 동시에 쓰지 않도록). 세션 로그 보관 규칙(D-020)은 트랙마다 최근 3개로 적용한다. 세부 마일스톤 현황 표도 M1·M2를 따로 둔다.
  6. **CI**: push마다 Actions가 검사·배포한다 (`concurrency: pages`, 순서대로 실행). 다른 트랙의 push 뒤 Actions가 실패하면 실패를 만든 커밋의 트랙이 고친다.
  7. **끝낼 때**: 트랙의 큰 마일스톤이 끝나면 회고를 쓰고 worktree를 지운다(`git worktree remove ../진동공부-Codex`). 다음 배정은 사용자가 정한다.
